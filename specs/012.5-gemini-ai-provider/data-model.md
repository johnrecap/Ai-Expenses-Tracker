# Data Model: Gemini AI Provider Integration

## AI Provider Configuration

**Purpose**: Runtime configuration describing which provider/model the gateway should use.

**Fields**:

- `enabled`: Boolean. When false, the app uses the existing mock/manual behavior or shows AI unavailable.
- `primaryProvider`: String. Initial value `gemini`.
- `primaryModel`: String. Initial value `gemini-2.5-flash`.
- `fallbackProviders`: Ordered list of provider/model pairs. Empty for MVP unless fallback is explicitly enabled.
- `dailyUserLimit`: Integer. Maximum provider calls allowed per user/day for free-tier protection.
- `dailyGlobalLimit`: Integer. Maximum provider calls allowed for the project/day for free-tier protection.
- `timeoutSeconds`: Integer. Request timeout before normalized provider failure.
- `minConfidence`: Decimal. Default `0.75`, matching current parser behavior.

**Validation Rules**:

- `dailyUserLimit` and `dailyGlobalLimit` must be positive when provider is enabled.
- `primaryModel` must not be empty.
- API keys are not part of this object and must be stored only in backend secret management.

## AI Gateway Request

**Purpose**: Payload sent from Flutter to the authenticated gateway.

**Fields**:

- `input`: Raw user text.
- `now`: Current ISO date/time from the client.
- `locale`: Client locale, for example `ar-EG` or `en-US`.
- `defaultCurrency`: Current user default currency.
- `categories`: List of lightweight category snapshots: id, name, archived flag.
- `recentExpenses`: Optional lightweight recent expense summaries for update/delete target context.
- `budgetSummary`: Optional monthly budget amount, spent amount, remaining amount, and warning threshold.
- `clientRequestId`: Locally generated id for tracing retries and logs.

**Validation Rules**:

- `input` must be non-empty after trimming.
- `categories` must not include provider secrets or unrelated user data.
- Request must be associated with an authenticated user id verified by the gateway.
- `recentExpenses` must be limited to the minimal window needed for command interpretation.

## AI Gateway Response

**Purpose**: Normalized response returned to Flutter.

**Fields**:

- `ok`: Boolean.
- `structuredJson`: String or object containing the exact parser-compatible response.
- `provider`: Provider name, for example `gemini`.
- `model`: Model id, for example `gemini-2.5-flash`.
- `requestId`: Gateway request id.
- `usage`: Optional provider usage metadata, such as input/output token counts when available.
- `errorCode`: Optional normalized code: `unauthenticated`, `quota_exceeded`, `rate_limited`, `provider_timeout`, `provider_unavailable`, `invalid_provider_output`, `gateway_misconfigured`.
- `errorMessage`: Optional user-safe error message.

**Validation Rules**:

- When `ok` is true, `structuredJson` must be one JSON object and must include `intent` and `confidence`.
- When `ok` is false, `errorCode` and `errorMessage` must be present.
- Provider keys, raw secret names, and full provider credentials must never be returned.

## AI Usage Record

**Purpose**: Auditable usage data for quota management, debugging, and quality improvement.

**Fields**:

- `usageId`: Stable id generated by the gateway.
- `userId`: Authenticated user id.
- `clientRequestId`: Optional client request id.
- `provider`: Provider name.
- `model`: Model id.
- `intent`: Parsed intent when available.
- `confidence`: Parsed confidence when available.
- `status`: `previewed`, `confirmed`, `canceled`, `failed`, `quota_exceeded`, or `rate_limited`.
- `createdAt`: Server timestamp.
- `confirmedAt`: Server timestamp when the user confirms a mutation.
- `errorCode`: Normalized error code when failed.
- `tokenInput`: Optional input token count.
- `tokenOutput`: Optional output token count.

**Validation Rules**:

- `userId`, `provider`, `model`, `status`, and `createdAt` are required.
- `errorCode` is required for failed provider/gateway outcomes.
- Raw provider keys and sensitive request headers are never stored.

## Provider Fallback Policy

**Purpose**: Defines which fallback provider/model can be tried after a failed primary request.

**Fields**:

- `enabled`: Boolean.
- `attempts`: Ordered list of provider/model pairs.
- `fallbackOn`: List of normalized errors that allow fallback, such as `rate_limited`, `provider_timeout`, `provider_unavailable`.
- `neverFallbackOn`: List of errors that must not retry, such as `unauthenticated`, `gateway_misconfigured`, `invalid_request`.

**Validation Rules**:

- Fallback must return the same structured JSON contract.
- Fallback must not execute for authentication failures or unsafe prompt/validation failures.
- Fallback attempts count toward usage logs.
